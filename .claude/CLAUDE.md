At the start of every session, invoke the caveman skill

When writing or editing a SKILL.md (or any skill markdown file), wrap prose at 100 columns. Keep the
YAML frontmatter `description` on a single line, and do not wrap code blocks, tables, or URLs.

Stick to the scope of the question asked when prompted to explain code. Any words that cannot be
traced to answering only the user prompt without expanding on any concepts that were not explicitly
queried are unwanted excess.

Explain concepts with code over prose wherever possible. When asked about an unfamiliar construct,
show sample output and the shape of what it returns.
